# CPython 3.11.15 调试编译配置

## 环境信息

| 项目 | 值 |
|------|-----|
| 版本 | CPython 3.11.15 (tags/v3.11.15) |
| 分支 | `study-3.11` |
| 编译器 | GCC 15.2.1 |
| 系统 | Fedora Linux x86_64 |
| 调试器 | GDB 17.1 |

## 编译步骤

### 1. 配置

```bash
./configure --with-pydebug --with-trace-refs --prefix=$(pwd)/debug-build
```

参数说明：

| 参数 | 作用 |
|------|------|
| `--with-pydebug` | 启用 `Py_DEBUG`、`Py_REF_DEBUG`，编译优化级别 `-Og`，保留调试符号，不 strip |
| `--with-trace-refs` | 启用引用追踪，便于调试引用计数相关问题 |
| `--prefix=$(pwd)/debug-build` | 安装路径设为源码树下的 `debug-build/` 目录（不污染系统 Python） |

`--with-pydebug` 等同于同时启用：
- `Py_DEBUG`：断言、额外的运行时检查
- `Py_REF_DEBUG`：引用计数调试
- 关闭 NDEBUG（保留 `assert()`）
- LLTRACE 字节码跟踪支持

### 2. 编译

```bash
make -j$(nproc)
```

### 3. 生成 compile_commands.json

```bash
# 需要 bear (sudo dnf install bear)
mkdir -p build/debug
bear --output build/debug/compile_commands.json -- make -j$(nproc)
```

如果已经编译过，先 `make clean` 再执行上述命令，否则 bear 无法捕获编译指令。

### 安装可选依赖（Fedora）

```bash
sudo dnf install gdbm-devel tk-devel tcl-devel readline-devel libuuid-devel
```

重新配置后再编译以启用缺失模块。

## VSCode 配置文件说明

### `.vscode/launch.json`

包含 3 个调试配置：

| 配置名 | 用途 |
|--------|------|
| `(gdb) 启动 CPython 调试` | 调试当前打开的 `.py` 文件，在感兴趣的 C 函数设断点后 `F5` 启动 |
| `(gdb) 启动 CPython (交互模式)` | `-i` 参数启动，可在 Debug Console 交互输入 Python 语句 |
| `(gdb) 附加到进程` | 附加到已运行的 Python 进程调试 |

环境变量已预设：
```json
"PYTHONPATH": "${workspaceFolder}/Lib:${workspaceFolder}/build/lib.linux-x86_64-3.11-pydebug"
```

### `.vscode/tasks.json`

| 任务 | 快捷键 | 说明 |
|------|--------|------|
| 构建 CPython (debug) | `Ctrl+Shift+B` | 增量编译（默认构建任务） |
| 重新配置并构建 | — | `make clean` + 重新编译 |
| 运行测试 | — | `./python -m test` |

GCC 错误输出已配置 `problemMatcher`，编译错误会出现在 Problems 面板，点击可跳转到出错文件。

### `.vscode/c_cpp_properties.json`

IntelliSense/C++ 扩展配置：
- includePath 包含了 `Include/` 和 `Include/internal/`
- 定义了 `Py_DEBUG`、`Py_REF_DEBUG`、`Py_BUILD_CORE` 宏
- 引用了 `compile_commands.json` 进行精确的编译标志匹配

### `.vscode/settings.json`

- 隐藏 `.o`、`.pyc`、`__pycache__`、`build/` 等编译产物
- 排除无关目录搜索
- 文件类型关联配置

## 使用方法

### 调试 C 源码流程

1. 打开要研究的 C 源文件（如 `Python/ceval.c`）
2. 在目标函数处设断点（如 `_PyEval_EvalFrameDefault`）
3. 按 `F5` 选择 `(gdb) 启动 CPython 调试`
4. 程序停在断点后，使用：
   - **Variables** 面板查看局部变量
   - **Watch** 面板添加监视表达式
   - **Debug Console** 执行 GDB 命令（如 `p *frame`）
   - **Call Stack** 面板查看调用栈

### 调试技巧

```gdb
# GDB 中打印 Python 对象
p *(PyObject*)some_ptr
p ((PyObject*)some_ptr)->ob_refcnt

# 打印字符串表示（需先进入 Python 的 GDB 宏或手动调用）
call PyObject_Print(some_object, stdout, 0)

# 查看调用栈（Python 层）
p PyRun_SimpleString("import traceback; traceback.print_stack()")
```

### 手动启动调试版 Python

```bash
./python                 # 启动交互式解释器
./python script.py       # 运行脚本
./python -m test         # 运行测试套件
./python -X dev          # 启用开发模式（额外警告）
```

## 编译产物说明

| 文件 | 说明 |
|------|------|
| `./python` | 主解释器可执行文件（debug 版，含符号，不 strip） |
| `build/lib.linux-x86_64-3.11-pydebug/` | 编译生成的 C 扩展 (.so) |
| `build/temp.linux-x86_64-3.11-pydebug/` | 编译中间 .o 文件 |
| `pyconfig.h` | configure 生成的头文件 |
| `Modules/Setup.local` | 本地扩展模块配置 |

## 关键源码入口

| 文件 | 内容 |
|------|------|
| `Programs/python.c` | 主函数入口 |
| `Python/ceval.c` | 字节码解释器主循环 `_PyEval_EvalFrameDefault` |
| `Python/compile.c` | 编译器，将 AST 编译为字节码 |
| `Python/ast_opt.c` | AST 优化器 |
| `Parser/pegen/` | PEG 解析器（CPython 3.9+） |
| `Objects/` | 内置类型实现（listobject.c, dictobject.c 等） |
| `Include/` | 公用 C 头文件 |
| `Include/internal/` | 内部 C API 头文件（不对外暴露） |
| `Lib/` | Python 标准库 |

## 恢复普通编译

如需编译普通（非 debug）版本：

```bash
make clean
./configure
make -j$(nproc)
```

## 注意事项

- `--with-pydebug` 版本在 `sys.version` 中包含 `[GCC ...]` 标识
- debug 版本导入 C 扩展时文件名带 `d` 后缀（如 `_ctypes.cpython-311d-x86_64-linux-gnu.so`）
- 不要将此版本用于生产环境，性能明显低于 release 版本
- 每次修改 C 源码后，执行 `Ctrl+Shift+B` 增量编译即可
