## 一、本周要回答的核心问题

带着这些问题去读源码、做实验，不要急着上网搜现成结论：

1. 一段 Python 代码（无论是 `python foo.py`、`python -c`、还是 REPL 输入），从进入解释器到产生结果，**依次经过哪几个阶段**？每个阶段的**输入**和**输出**分别是什么数据结构？
2. 这些阶段分别由源码树里的**哪些文件 / 函数**负责？
3. “编译”在 Python 里到底编译成了什么？它和 Go 的“编译”有什么本质区别？
4. `code object` 是什么？它里面装了哪些东西？谁产生它、谁消费它？
5. 解释器真正“执行”的入口函数是哪个？程序是怎么一路调用到它的？

## 三、阅读资料 / 查阅线索

> 原则：先在**本仓库代码**里找答案，文档/书/视频用来补全和验证你的理解。下面只指“去哪看、它扮演什么角色”，不解释它怎么工作。

### A. 仓库内代码（按流水线顺序，找“入口”，不必逐行读）
- 进程入口：`Programs/python.c`（`main`）→ `Modules/main.c`（`Py_RunMain` → `pymain_run_python`）—— 程序如何启动、如何决定运行文件 / 模块 / `-c` / REPL。
- 运行源码：`Python/pythonrun.c`（`run_mod`、`run_eval_code_obj` 等）—— 运行阶段的协调点。
- 词法：`Parser/tokenizer.c`、`Parser/token.c`。
- 语法（PEG）：`Parser/pegen.c`、`Parser/parser.c`（后者由 `Grammar/python.gram` 自动生成）。
- AST：`Parser/Python.asdl`（AST 节点定义）、`Python/Python-ast.c`（由 asdl 生成）、`Python/ast.c`（AST 校验）。
- 符号表：`Python/symtable.c`（`_PySymtable_Build`）。
- 编译：`Python/compile.c`（`_PyAST_Compile`）。
- code object：`Objects/codeobject.c`、`Include/cpython/code.h`。
- 求值：`Python/ceval.c`（`PyEval_EvalCode` → `_PyEval_EvalFrameDefault`）、`Include/opcode.h`、`Lib/opcode.py`。

### B. 官方文档 / 网页
- CPython Developer’s Guide：
  - Design of CPython’s compiler — https://devguide.python.org/internals/compiler/
  - Guide to the parser — https://devguide.python.org/internals/parser/
- 标准库文档：
  - `dis` — https://docs.python.org/3.11/library/dis.html
  - `ast` — https://docs.python.org/3.11/library/ast.html
- PEP 617《New PEG parser for CPython》（3.9 起替换旧 parser）— https://peps.python.org/pep-0617/

### C. 书籍
- **《CPython Internals》** — Anthony Shaw（Real Python）。前几章正好讲编译/解析流水线。注意：成书基于 3.9，**求值循环与帧在 3.11 有较大改动**，本周关注流水线整体结构即可，细节以本仓库 3.11 代码为准。
- **《Inside The Python Virtual Machine》** — Obi Ike-Nwosu（网上可免费阅读）。偏重虚拟机执行视角，可作补充。

### D. 视频（可选）
- Philip Guo 的 “CPython internals” 系列课程（YouTube 搜作者名 + “CPython internals”），逐文件带读 CPython 源码，适合建立全局观。
