## 学习策略

**核心思路**：每个阶段锚定一个具体问题，读源码找答案，写实验验证。

推荐工作流：
1. 在 C 源码中找到感兴趣的函数，设断点
2. F5 启动 GDB 调试，在 Debug Console 中执行 Python 语句触发断点
3. 观察调用栈、局部变量、对象内存布局
4. 写一个小脚本验证行为是否符合预期

## 第一阶段：对象模型（1-2 周）

Python 中一切皆对象。理解对象模型是读懂所有其他源码的前提。

### 任务 1：`PyObject` 内存布局

**问题**：`a = 42` 背后是什么样的 C 结构体？`id()` 返回的是什么？

**关键文件**：
- `Include/object.h` — `PyObject`、`PyVarObject` 结构体定义
- `Include/cpython/object.h` — `PyObject_HEAD` 宏展开

**动手实验**：
```python
import ctypes, sys

# 观察整数对象的内存布局
a = 42
b = 42
print(id(a), id(b))          # 小整数是同一个对象吗？
print(sys.getrefcount(a))    # 引用计数是多少？

# 用 ctypes 读取 ob_refcnt
refcnt = ctypes.c_long.from_address(id(a)).value
print(refcnt)  # 与 sys.getrefcount 对比
```

**源码断点**：`_PyObject_Init`、`PyObject_New`

### 任务 2：小整数缓存池

**问题**：为什么 `a is b` 对 `-5` 到 `256` 成立，但 `257` 就不成立了？

**关键文件**：`Objects/longobject.c` — 搜索 `small_ints`

**动手实验**：
```python
a, b = 256, 256
print(a is b)   # True — 来自小整数缓存
a, b = 257, 257
print(a is b)   # False — 两个不同的对象
```

### 任务 3：字符串的 intern 机制

**问题**：字符串字面量何时 intern？标识符规则是什么？

**关键文件**：`Objects/unicodeobject.c` — `PyUnicode_InternInPlace`

**动手实验**：
```python
a = "hello"
b = "hello"
print(a is b)   # 字面量自动 intern

a = "hello world!"
b = "hello world!"
# 这两种分别是否 intern？为什么？
```

## 第二阶段：解释器执行循环（2-3 周）

这是 CPython 的心脏，理解了你就能回答"Python 为什么慢"。

### 任务 4：追踪 `for i in range(3): pass` 的完整执行过程

**问题**：这行代码经历了 词法分析 → 语法分析 → AST → 字节码 → 执行 的哪些步骤？

**关键文件**：
- `Python/ceval.c` — `_PyEval_EvalFrameDefault`，字节码解释器主循环
- `Python/compile.c` — 编译器入口
- `Parser/pegen/` — PEG 解析器

**动手实验**：
```python
import dis
code = compile("for i in range(3): pass", "<test>", "exec")
dis.dis(code)
# 对照 ceval.c 中的 switch-case，找到每个字节码对应的 C 代码
```

**源码断点**：在 `_PyEval_EvalFrameDefault` 的 `main_loop` 标签处设断点，单步跟踪几次循环，观察 `next_instr` 指针如何推进。

### 任务 5：函数调用栈帧

**问题**：`def f(): g()` 调用时，栈帧是怎么创建和销毁的？

**关键文件**：
- `Objects/frameobject.c` — 帧对象
- `Python/ceval.c` — `_PyEval_EvalFrameDefault` 中调用逻辑
- `Include/cpython/frameobject.h` — `_PyInterpreterFrame` 结构体

**动手实验**：
```python
import inspect

def g():
    frame = inspect.currentframe()
    print(frame.f_back)  # 指向上级帧
    print(frame.f_locals)

def f():
    g()

f()
```

**源码断点**：`_PyEval_EvalFrameDefault` 入口，观察 `frame->f_back` 链接。

### 任务 6：`dict` 的查找过程

**问题**：`d[key]` 在 C 层面是怎样找到值的？幻数 `DKIX_EMPTY` 是什么？

**关键文件**：`Objects/dictobject.c`、`Objects/dict-common.h`

**动手实验**：
```python
d = {"a": 1, "b": 2}
# 在 GDB 中观察 d 的 ma_keys 和 ma_values 数组
```

**源码断点**：`dict_get`, `dict_get_impl` → `find_key` 或 `dictkeys_generic_lookup`（新版用 Unicode 快速路径）。

## 第三阶段：内存管理（1-2 周）

### 任务 7：引用计数与循环垃圾回收

**问题**：Go 有三色标记 GC，Python 的引用计数 + 分代回收是怎么配合的？

**关键文件**：
- `Include/object.h` — `Py_INCREF` / `Py_DECREF` 宏
- `Modules/gcmodule.c` — `collect()` 循环垃圾回收
- `Objects/object.c` — `_Py_Dealloc`

**动手实验**：
```python
import gc, sys

# 循环引用
lst = []
lst.append(lst)
print(sys.getrefcount(lst))   # 2 (lst 自身 + getrefcount 参数)
del lst                        # 引用还剩下 1（循环）
print(gc.collect())            # gc 回收它
```

**源码断点**：`_Py_Dealloc`、`gc_collect_main`

### 任务 8：对象内存池（obmalloc）

**问题**：Python 的小对象分配为什么不直接用 `malloc`？

**关键文件**：`Objects/obmalloc.c` — `_PyObject_Malloc`、pymalloc 分配器

**动手实验**：
```python
import sys
# 创建大量小对象，观察内存使用
objs = [object() for _ in range(100000)]
print(sys.getsizeof(object()))  # 单个 object 多少字节？
```

## 第四阶段：GIL 与并发模型（1 周）

这个阶段与你 Go 背景最有对比价值。

### 任务 9：GIL 的获取与释放

**问题**：GIL 是怎么实现互斥的？Python 3.11 的"每解释器 GIL"改了什么？

**关键文件**：`Python/ceval_gil.c`

**动手实验**：
```python
import threading, time

counter = 0

def worker():
    global counter
    for _ in range(10**6):
        counter += 1

t1 = threading.Thread(target=worker)
t2 = threading.Thread(target=worker)
t1.start(); t2.start()
t1.join(); t2.join()
print(counter)  # 远小于 2*10^6，为什么？
# 提示：counter += 1 对应多条字节码，GIL 在字节码之间释放
```

**源码断点**：`take_gil`、`drop_gil`

### 任务 10：对比 Go 和 Python 并发

**问题**：从实现角度看，Goroutine 和 Python 线程的本质区别是什么？

**关键文件**：`Python/thread_*.c`、`Python/ceval_gil.c`

| 维度 | Go (Goroutine) | CPython (Threading) |
|------|---------------|---------------------|
| 调度模型 | M:N（用户态调度） | 1:1 内核线程，GIL 互斥 |
| 栈 | 动态扩缩（起始 2KB） | 固定栈（pthread 默认） |
| 阻塞 | 仅阻塞当前 G | 阻塞整个 OS 线程 |
| 适用场景 | CPU + IO 混合 | IO 密集型（或用 multiprocessing） |
